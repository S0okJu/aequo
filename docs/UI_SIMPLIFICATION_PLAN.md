# Aequo — UI 단순화 계획 (레이아웃 · 글 목록 · 사이드바 · 리더 · AI 채팅 · 설정)

> 이 문서는 `docs/READER_ANNOTATIONS_PLAN.md`(M12~M16)와 별도로 분리된, 메인 화면의 디자인/사용성 정리 계획이다.
> 방향: **"기본으로는 꼭 필요한 것만 보이고, 나머지는 필요할 때 드러난다."** 기능을 빼는 작업이 아니라
> 노출 방식을 바꾸는 작업이다 — 지금 있는 기능(AI 질문, 저장, 폴더 이동, 전문 추출, 형광펜/메모)은 전부 유지한다.
> 아직 코드는 건드리지 않았고, 이 문서는 설계/합의용 계획서다.

## 0. 현재 구조 요약 (왜 이렇게 바꾸는지의 전제)

- 메인 화면은 `src/routes/+page.svelte`의 7트랙 grid다: `사이드바 | 핸들 | 글 목록 | 핸들 | 리더 | 핸들 | AI`.
  트랙 너비는 전부 px 숫자로 계산되어(`layoutSidebarWidth`, `postListComputedWidth`, `readerPaneWidth`, `effectiveAiWidth`)
  `grid-template-columns` transition으로 애니메이션된다.
- AI 패널은 `aiPanelOpen`(localStorage `aequo:aiPanelOpen`)이 **기본값 `true`** 라서, 글을 고르기 전에도
  "Select a post to start a conversation about it."만 띄운 채 기본 400px를 차지한다. 닫으면 40px `ai-rail`이 남는다.
- 글 목록(`PostsFeed.svelte`)은 글 하나가 카드(`.post`: 1px 테두리 + `--radius-lg` + 흰 배경, 회색 pane 위)이고,
  카드 한 장에 글자 아바타 · 피드 전체 이름 · 절대 시각(`formatTime`: `dateStyle/timeStyle: 'short'`) · 안 읽음 점 · 별 ·
  제목 · `FeedContent compact` 요약이 들어간다. 날짜 그룹 제목(`.date-heading`)이 이미 있어 절대 시각과 정보가 중복된다.
- RSS 요약에 WordPress 계열 피드가 붙이는 `"The post … appeared first on …"` 꼬리 문구가 그대로 노출된다
  (`fetch/parser.rs`는 `entry.summary`를 그대로 저장).
- 사이드바(`FeedList.svelte`)에 설정 진입점이 두 개다: `FOLDERS` 라벨 옆 `Manage →`, 하단 `Manage feeds` 버튼(`+page.svelte`).
  피드 행마다 `⋮`(`feed-move-trigger`)가 항상 보여 제목이 일찍 잘린다.
- 리사이즈 핸들 3개가 각각 6px `--color-bg-secondary` 띠로 렌더링되어 pane 사이에 두꺼운 회색 줄처럼 보인다.
- `--color-bg-secondary`(회색)가 사이드바 · 글 목록 · 핸들 · body에 모두 쓰이고, 흰색은 카드와 리더에만 쓰인다.
- 리더 헤더(`PostReader.svelte`)에 `● Full article · cached` / `Refresh` / `Read original site` 상태 줄이 항상 있다.
- AI 패널 하단에 `Runs through your signed-in local CLI · No API key in Aequo` 문구가 항상 있다(`AiPanel.svelte`).
- 전역 키보드 단축키가 없다. 키 처리는 리사이즈 핸들/메뉴/개별 행의 `onkeydown`뿐이다(이 계획에서도 추가하지 않음, §3.8).
- 11/15 스크린샷 기준으로 창 아래쪽이 비고(pane이 창 높이를 다 채우지 못함) 가로 스크롤바가 생기는 문제가 보였다.
  이후 `initialViewportWidth()`를 `clientWidth` 기준으로 바꾼 커밋이 있으므로 재현 여부부터 확인한다.

## 1. 목표 / 비목표

### 목표
- 첫 화면에서 눈에 들어오는 요소 수를 줄인다: pane 3개, 글 한 건당 3줄(출처·시간 / 제목 / 요약).
- "안 읽음 / 저장됨 / 선택됨" 상태를 색 점·배지 대신 **굵기·명도**로 구분한다.
- 설정·이동·저장 같은 보조 조작은 hover/포커스 시에만 드러나게 한다(키보드 포커스로도 반드시 보이게).

### 비목표 (이 계획 범위 아님)
- 새 기능 추가(태그, 동기화, OPML 등) — 예외: favicon, AI 응답 중지, 피드 검색, RSS 리더 기본 기능(§3.14: 안 읽은 글만 보기,

- 모바일/좁은 창 전용 레이아웃

## 2. 목표 레이아웃

```
현재                                        변경 후
┌────┬──────────┬────────┬──────┐          ┌────┬──────────┬───────────────────┐
│피드│ 카드 목록 │ 리더   │ AI   │          │피드│ 목록      │ 리더          [✦] │
│    │          │        │(빈칸)│    →     │    │ (얇은 행) │                   │
└────┴──────────┴────────┴──────┘          └────┴──────────┴───────────────────┘
                                             ✦ 버튼으로 리더 오른쪽에 AI 패널
```

- 기본 상태: `사이드바 | 목록 | 리더`. 글을 고르지 않았을 때는 목록이 남는 폭을 쓴다(현재 동작 유지).
- AI 패널은 **기본 닫힘**. 열면 지금처럼 오른쪽 grid 트랙으로 들어온다(오버레이가 아니라 트랙 — 리더 본문을 가리지 않기 위해).
- 닫혔을 때의 40px `ai-rail`은 제거한다. 여는 입구는 리더 헤더의 ✦ 버튼과 기존 "Ask AI" 선택 툴바 두 곳이다.
- **AI는 "열린 글에 딸린 기능"으로 둔다** (Readwise Reader의 Ghostreader, Feedly Leo 등 리더 앱의 보편적 방식).
  - 글이 열려 있지 않으면 AI 패널 트랙도 렌더링하지 않는다. "Select a post…" 빈 상태는 없앤다.
  - 패널을 연 상태는 기억한다(`aequo:aiPanelOpen`): 패널을 연 채 글을 닫았다가 다른 글을 열면 패널도 다시 열린 상태로 나타난다.
    이는 Readwise Reader 오른쪽 패널, IDE 보조 패널의 일반적 동작과 같다.
  - 즉 "AI 패널 표시 = `aiPanelOpen && selectedItem !== null`".

## 3. 영역별 설계

### 3.1 글 목록 — 카드 → 행 (`PostsFeed.svelte`)

```
[ico] The New Stack · 2시간 전                             ☆  ← 별은 hover/포커스/저장됨일 때만
Claude Fable 5.2 vs. Fable 5.1: Fewer refusals…               ← 안 읽음: 굵게 + --color-text
Anthropic's Claude Fable 5.2 promises fewer lower token       ← 요약 최대 2줄(결정됨), --color-text-secondary
prices, but those changes played out very differently…
──────────────────────────────────────────────────────────
D2 Blog · 5시간 전
이미 읽은 글은 보통 굵기 + --color-text-secondary
```

- `.post`의 테두리·radius·카드 배경 제거 → 행 사이 1px `--color-border` 구분선. 목록 pane 배경은 `--color-bg`(흰색).
- 선택된 행: `--color-selection-bg` 배경. hover: `--color-hover-bg`.
- **안 읽음 점(`.unread-dot`) 제거**, 대신 제목 `font-weight`로 구분(안 읽음 650 / 읽음 450 + secondary 색).
  스크린리더용으로 행에 `aria-label`이나 시각적으로 숨긴 "안 읽음" 텍스트를 남긴다.
- **글자 아바타(`.avatar`, 28px 원) → 16px favicon**으로 교체하고 출처 줄 안에 인라인으로 넣는다(§3.12).
  favicon이 없거나 아직 받지 못한 피드는 아이콘 자리를 비우지 않고 회색 원 안 첫 글자(현재 아바타 축소판)로 대체한다.
- 요약은 `-webkit-line-clamp: 2`로 **최대 2줄**. `FeedContent compact`가 이미 줄 제한을 하고 있다면 값만 맞춘다.
- 시간: `formatTime` → 상대 시간(`방금`, `N분 전`, `N시간 전`, 하루 이상은 `M월 D일`). `Intl.RelativeTimeFormat` 사용,
  `<time datetime>`과 `title`에는 절대 시각을 그대로 둔다.
- 피드 이름: `" | "` · `" - "` 앞부분만 표시하는 `shortFeedTitle()` 유틸을 `$lib`에 두고 사이드바와 공유한다.
- `.feed-context`(상단 "보기 이름 + N unread" 줄)는 유지하되 pill 대신 회색 텍스트로.
- `Scroll for more` 문구 → 스피너만(로딩 중일 때) 또는 아무것도 표시하지 않음.

### 3.2 요약 꼬리 문구 제거 (`fetch/parser.rs`)

- `"The post <title> appeared first on <site>."` 패턴(앞의 `<p>` 포함)을 저장 전에 잘라낸다.
- 프론트에서 정규식으로 지우는 방법도 가능하지만, 요약은 AI 컨텍스트와 리더 fallback에도 쓰이므로 **파서에서 한 번** 처리한다.
- 이미 저장된 item은 재수집 시 자연히 갱신되지 않으므로(upsert 정책 확인 필요) 프론트에 동일 패턴의 방어 코드도 둔다.
- `tests/fixtures/`에 꼬리 문구가 있는 RSS 2.0 fixture를 추가해 파서 테스트를 만든다.

### 3.3 사이드바 (`FeedList.svelte`, `+page.svelte`)

- 설정 진입점 하나로 통합: `Manage →` 버튼과 하단 `Manage feeds` 텍스트 버튼 제거 →
  사이드바 하단에 아이콘 버튼 두 개 `+`(피드 추가) · ⚙(설정). `+`는 **피드 추가 다이얼로그**를 연다(§3.11).
  아이콘 사전(`src/lib/icons/index.ts`)에 `plus`를 추가해야 한다.
- 폴더 이름 변경/삭제, 새 폴더 만들기는 사이드바에서 바로 할 수 있게 **우클릭 컨텍스트 메뉴**를 둔다
  (NetNewsWire·Reeder 등 데스크톱 RSS 앱의 일반적 방식). 피드 행 우클릭: 폴더로 이동 · 새로고침 · 설정 열기 · 구독 해제.
  기존 `⋮` 메뉴와 같은 메뉴 컴포넌트를 공유한다.
- `⋮`(`feed-move-trigger`)는 행 hover, 행 내부 `:focus-within`, 메뉴 열림(`aria-expanded="true"`) 상태에서만 보인다.
  숨김은 `visibility`/`opacity`로 처리해 탭 순서와 레이아웃 폭은 유지한다(제목이 hover 때 덜컹이지 않게 폭은 예약하지 않고 overlay로 띄우는 것도 검토).
- 안 읽은 수(`.count`)는 배경 없는 `--color-text-tertiary` 숫자. 0이면 숨김(현재와 동일).
- `FOLDERS` 라벨 제거, `UNFILED` 라벨은 폴더가 1개 이상일 때만 아주 흐리게 유지(드롭 타깃 안내 역할이 있으므로).
- All / Today / Starred 아이콘 일관성: All에도 아이콘(`inbox` 계열, 신규)을 넣는다.

### 3.4 Pane 경계 / 리사이즈 핸들 (`+page.svelte`)

- grid 트랙의 6px 핸들은 유지하되(계산식이 6px에 의존하므로) 시각적으로는 **투명 배경 + 가운데 1px `::before` 선**만 그린다.
- hover/`:focus-visible`에서 선을 2px accent로. 기존 pane별 `border-right`/`border-left`는 제거해 선이 두 줄로 겹치지 않게 한다.

### 3.5 배경 토큰 사용처 정리

- 회색 `--color-bg-secondary`: 사이드바에만. 목록·리더·AI 패널은 `--color-bg`.
- body/html 배경은 그대로 둔다(창 리사이즈 시 깜빡임 방지).
- 토큰 값 자체는 바꾸지 않는다(다크 모드 영향 최소화).

### 3.6 리더 헤더 (`PostReader.svelte`)

```
The New Stack · 2시간 전                        ☆   ↗   ✦   ✕
Claude Fable 5.2 vs. Fable 5.1: Fewer refusals…
```

- 헤더는 출처·시간·제목 + 오른쪽 아이콘 버튼(저장 / 원문 열기 / AI / 닫기). 각 버튼에 `aria-label`과 `title`.
- `article-state` 상태 줄(`Full article · cached`)과 `Refresh` 버튼은 기본 숨김. 다음 경우에만 노출:
  - 전문 추출 실패 → 기존 `.fallback-notice`가 이미 처리(유지)
  - 전문 로딩 중 → 헤더 아래 얇은 진행 표시 또는 "전문 불러오는 중…" 한 줄
- `Refresh`는 `⋯` 메뉴 또는 fallback notice 안으로 이동.

### 3.7 AI 패널 표시 규칙 (`+page.svelte`)

- `aequo:aiPanelOpen` 기본값 `true` → `false`. 이미 저장된 값이 있는 사용자는 그 값을 존중한다.
- 표시 조건은 §2의 "`aiPanelOpen && selectedItem !== null`". 패널 내부 디자인은 §3.9.

### 3.8 키보드 단축키 — 제외 (결정됨)

전역 키보드 단축키(`j/k`, `⌘N`, `⌘,`, `⌘F` 등)는 **이 계획에서 만들지 않는다.** 모든 동작은 화면의 버튼으로 한다.
다음은 단축키가 아니라 기존 동작·표준 입력 동작이므로 유지한다:
- 버튼/행의 Tab 포커스, Enter/Space 실행, 메뉴·다이얼로그의 `Esc` 닫기(접근성, `<dialog>` 기본 동작)
- 설정 화면의 기존 `Esc` → 돌아가기
- 채팅 입력창의 Enter 전송 / Shift+Enter 줄바꿈, 검색 입력창의 `Esc` 검색 종료

### 3.9 AI 채팅 패널 (`AiPanel.svelte`)

**현재 문제** — 대화 내용이 나오기까지 위에서부터 6개 층이 쌓여 있다:
`✦ AI assistant · ● Local · ›` → `Chat | History` 탭 → `ASSISTANT` 라벨 → `Codex | Claude | New chat` →
`DISCUSSING <글 제목> ↗ New chat` 카드 → 메시지 → 입력창 + 안내 문구 → `Runs through your signed-in local CLI…` 푸터.
기능별로 보면:

- 바로 옆 리더가 이미 같은 글을 보여주고 있어 `DISCUSSING` 카드는 정보가 중복된다.
- `Local` 배지와 하단 푸터 문구는 매번 볼 필요가 없는 설정 정보다.
- provider 선택이 저장되지 않는다(`provider` 상태가 매번 초기값으로 시작).
  또 provider를 바꾸면 `selectProvider()`가 `startNewChat()`을 불러 **보고 있던 대화가 경고 없이 사라진다.**
- 다른 글로 넘어가면 `$effect`가 항상 새 채팅으로 리셋한다. 이 글에 이전 대화가 있어도 History 탭에 들어가야만 찾을 수 있다.
- 메시지마다 `You` / `Claude` 라벨이 붙고, 사용자/AI 메시지의 시각적 구분이 약하다.
- 응답을 기다리는 중 **멈출 방법이 없다**(`ai.rs`에 취소 커맨드 없음). 응답도 한 번에 도착한다(스트리밍 아님).
- 본문 선택 → "Ask AI" 시 인용문이 입력창에 `> 인용문` 마크다운 텍스트로 들어가 사용자가 직접 지우거나 편집해야 한다.
- 글을 바꾸면 `sending = false`로 리셋되는데, 진행 중이던 응답이 어디로 가는지 사용자에게 보이지 않는다(동작 확인 필요).

**변경 후** (ChatGPT·Claude·Cursor 사이드 채팅의 보편적 구성):

```
┌──────────────────────────────────────┐
│ Claude ▾                  🕘  ✎   ✕ │  ← 한 줄 헤더: provider · 기록 · 새 대화 · 닫기
├──────────────────────────────────────┤
│                                      │
│   [요약하기] [핵심 정리] [쉽게 설명]   │  ← 빈 상태: 칩 3개만
│   이전 대화 · 어제 "핵심 정리…"  →     │  ← 이 글의 최근 대화가 있으면 1~3개
│                                      │
│              ┌──────────────────┐    │
│              │ 사용자 질문 (말풍선)│    │  ← 사용자: 오른쪽 정렬, 옅은 배경
│              └──────────────────┘    │
│ AI 답변은 배경 없이 본문처럼 전체 폭     │  ← AI: 라벨 없음, hover 시 복사 아이콘
├──────────────────────────────────────┤
│ ┃ "인용된 문장…"                ✕   │  ← 인용은 입력창 위 칩
│ 이 글에 대해 질문하기…           [↑] │  ← 전송 중엔 [■] 중지
└──────────────────────────────────────┘
```

- **헤더 한 줄로 통합**: `AI assistant` 제목, `Local` 배지, `ASSISTANT` 라벨, `Chat | History` 탭을 제거한다.
  - provider는 드롭다운(`Claude ▾`)으로 바꾸고 선택은 localStorage `aequo:aiProvider`에 저장한다.
  - **대화 중 provider 변경 (결정됨: 확인 없이 바로 새 대화, 이전 대화는 기록에서 되돌아갈 수 있게)**:
    - 세션은 provider별 CLI에 묶여 있어 한 대화 안에서 provider를 섞을 수 없다. 그래서 드롭다운을 바꾸면 **곧바로 새 대화**를 시작한다.
      확인 다이얼로그(클릭 2번)나 비활성화(새 대화 버튼을 먼저 눌러야 하는 2단계)보다 조작이 한 번으로 끝난다.
    - 이전 대화는 지워지지 않는다(CLI transcript + `ai_sessions`에 그대로 있음). 메시지 영역 맨 위에
      "Codex 대화는 기록에 저장됨 · 돌아가기" 한 줄을 보여주고, `돌아가기`를 누르면 그 세션과 provider로 즉시 복귀한다.
      이 줄은 새 대화에서 첫 메시지를 보내면 사라진다.
    - 입력창에 쓰던 내용(`draft`)과 인용 칩은 provider를 바꿔도 유지한다 — 지금은 `startNewChat()`이 상태를 초기화하지만 `draft`는 남기도록 바꾼다.
    - 응답을 받는 중(`sending`)에는 드롭다운을 비활성화한다(진행 중인 요청의 provider가 바뀌는 혼란 방지).
  - 🕘 기록은 탭 대신 **팝오버 목록**으로 연다. 기존 History 탭의 내용(provider, 제목, 시각, 삭제 확인)을 그대로 옮긴다.
    "CLI 기록에서는 삭제되지 않음" 안내는 삭제 확인 문구 안으로 넣는다.
  - ✎ 새 대화 버튼은 현재 `New chat` 텍스트 버튼을 대체한다.
- **`DISCUSSING` 카드 제거.** 어떤 글에 대한 대화인지는 리더가 옆에 있어 자명하다.
  원문 링크도 리더 헤더 ↗ 버튼과 중복이므로 제거한다.
- **빈 상태 단순화**: 아이콘·`What would you like to know?` 제목·설명 문단을 빼고, 빠른 질문 칩 3개만 남긴다.
  `Summarize` 버튼만 다른 스타일이던 것을 칩 스타일로 맞춘다. 원문 URL이 없을 때는 요약 칩만 비활성화하고 `title`로 이유를 알린다.
  - 이 글에 이전 대화가 있으면 칩 아래에 최근 대화 1~3개를 "이전 대화"로 보여준다(클릭 시 이어서 대화).
    자동으로 이전 대화를 여는 대신 고를 수 있게 한다 — 예상치 못한 transcript 로드를 피하고 "새 질문"을 기본으로 둔다.
- **메시지 표현**: 사용자 메시지는 오른쪽 정렬 말풍선(`--color-hover-bg` 배경), AI 메시지는 배경 없는 전체 폭 본문.
  `You`/`Claude` 역할 라벨은 제거한다(대화 중 provider가 바뀌지 않으므로 헤더 표시로 충분하다).
  `Copy` 텍스트 버튼 → hover/포커스 시 나타나는 복사 아이콘, 누르면 잠깐 체크 아이콘으로 바뀐다.
- **입력창**:
  - `Enter to send · Shift+Enter for a new line` 상시 안내 문구는 제거한다(채팅 UI의 보편적 관례).
    `Response usually takes a moment`도 제거하고, 진행 표시는 메시지 영역의 `thinking` 표시 하나로 둔다.
  - placeholder는 `이 글에 대해 질문하기…`.
  - 한글 IME 조합 중 Enter로 전송되지 않도록 `event.isComposing` 체크를 추가한다(현재 `onkeydown`에는 없다).
  - 패널이 열리면 입력창에 자동 포커스한다.
- **인용 칩**: `pendingQuote`를 입력창 텍스트에 넣지 않는다. 입력창 위에 왼쪽 세로선이 있는 인용 칩으로 보여주고,
  ✕로 뺄 수 있게 한다. 전송할 때만 프롬프트 앞에 인용을 붙인다 — 사용자가 마크다운을 직접 다룰 필요가 없다.
- **중지 버튼**: 전송 중에는 전송 버튼 자리에 ■ 중지를 둔다. 백엔드에 `cancel_ai_message` 커맨드를 추가해
  실행 중인 CLI 서브프로세스를 종료한다(스트리밍과 같은 child 보관 구조를 쓴다 — 아래 스트리밍 항목). 중지된 경우 "응답을 중지했습니다" 상태를 남긴다.
- **글 전환 중 응답**: 응답 대기 중에 다른 글로 넘어가면 그 응답은 해당 글의 세션에 저장되고, 다시 그 글을 열었을 때
  "이전 대화"에서 볼 수 있어야 한다. 현재 구현이 그렇게 동작하는지 먼저 확인하고, 아니라면 이 단계에서 맞춘다.
- **푸터 제거**: `Runs through your signed-in local CLI · No API key in Aequo`는 설정 > AI로 옮긴다(§3.10).
  패널에는 CLI를 찾지 못했거나 로그인이 안 된 경우처럼 **문제가 있을 때만** 기존 `.error-card`로 안내하고,
  "설정에서 확인" 링크를 함께 준다.
- **스트리밍 응답 (v1.0.0 포함, UI10)**: 답변이 생성되는 대로 화면에 흘러나오게 한다. 설계:
  - **현재**: `send_ai_message`가 `command.output()`(`ai.rs`)으로 CLI가 끝날 때까지 기다린 뒤 결과 전체를 한 번에 반환한다.
    Claude는 `--output-format json`, Codex는 `exec --json`으로 실행 중이다.
  - **백엔드**: `command.output()` → `spawn()` + `stdout`을 `BufReader::lines()`로 한 줄씩 읽는 구조로 바꾼다.
    - Claude: `--output-format stream-json`(+ `--verbose`, 부분 토큰이 필요하면 `--include-partial-messages`)로 바꾸면 JSON Lines로 텍스트 조각이 온다.
    - Codex: `exec --json`은 이미 JSON Lines 이벤트를 내보낸다. 다만 토큰 단위가 아니라 **단계 단위**(추론, 도구 호출, 메시지 완료)일 수 있다.
      이 경우 메시지는 완료 시점에 한 번에 표시하고, 그 전에는 단계 상태("웹 페이지 읽는 중…")를 `thinking` 표시 자리에 보여준다.
    - 각 CLI의 정확한 이벤트 형식과 플래그는 **설치된 버전에서 실제 출력을 캡처해 fixture로 저장한 뒤** 파서를 작성한다(버전마다 다를 수 있음).
    - 파싱한 조각을 Tauri 이벤트 `ai-stream`(`{ requestId, kind: 'delta' | 'status' | 'done' | 'error', text, sessionId }`)으로 보낸다.
      커맨드 자체는 요청을 시작하고 `requestId`를 즉시 반환한다.
    - 기존 `CLI_TIMEOUT`은 "전체 응답 시간" 대신 "마지막 출력 이후 무응답 시간"으로 바꾼다(긴 답변이 중간에 잘리지 않게).
  - **중지와 같은 구조를 공유**: 실행 중인 child process를 `requestId`별로 보관하는 맵(`Mutex<HashMap<String, Child>>`)을 두고,
    `cancel_ai_message(requestId)`가 해당 프로세스를 종료한다. 중지하면 그때까지 받은 텍스트는 남기고 "중지됨" 표시를 붙인다.
  - **프론트**: `requestId`로 이벤트를 걸러 마지막 AI 메시지에 텍스트를 이어 붙인다. 마크다운은 조각마다 다시 렌더링하되
    `requestAnimationFrame`으로 묶어 프레임당 한 번만 렌더링한다. 사용자가 위로 스크롤해 있으면 자동 스크롤을 멈춘다.
  - **글 전환 중 응답**: 스트림은 `requestId`에 묶여 있으므로 다른 글로 넘어가도 백엔드에서 계속 받아 세션에 남는다.
    화면에는 현재 글의 요청 이벤트만 반영한다.
  - **테스트**: 캡처한 fixture로 각 CLI 파서 단위 테스트, 중지 시 프로세스 종료 확인, 무응답 타임아웃.

### 3.10 설정 화면 (`routes/settings/+page.svelte`, `FeedSettings.svelte`, `FolderSettings.svelte`)

**현재 문제**

- 제목이 `Feed settings`인데 Storage·Appearance까지 들어 있다. `PREFERENCES` 눈썹 라벨과 소개 문단이 더해져 헤더가 3단이다.
- 상단 가로 탭 4개(`Feeds | Folders | Storage | Appearance`)에 AI 관련 설정이 없다
  (AI 동작 방식 안내가 AI 패널 푸터에 박혀 있다).
- **피드 탭이 피드 수에 비례해 매우 길어진다.** 피드 하나가 카드 한 장인데, 그 안에 제목·URL, 메타 pill 4개
  (`RSS` · `Every 15m` · `N unread` · `Next check …`), 폴더 select, 새로고침 주기 select, `Show in All` 스위치,
  `Refresh`·`Unsubscribe` 버튼이 전부 펼쳐져 있다. 피드 20~30개면 원하는 피드를 찾기 어렵고, 검색도 없다.
- 오류가 난 피드가 목록 중간에 섞여 있어 한눈에 찾기 어렵다.
- 피드 추가 폼이 피드 탭 맨 위에 항상 펼쳐져 있다.
- 폴더 관리가 별도 탭이라, 피드를 폴더에 넣는 작업(피드 탭 select)과 폴더를 만드는 작업(폴더 탭)이 나뉘어 있다.
- 저장 방식이 섞여 있다: Appearance·피드 설정은 바꾸면 바로 저장되는데, Storage만 `Save policy` 버튼을 눌러야 저장된다.

**변경 후** (macOS 설정 창·NetNewsWire·Reeder의 보편적 구성):

```
┌──────────────┬─────────────────────────────────────────────┐
│ ‹ 돌아가기    │ 구독                         [🔍 검색] [+ 추가] │
│              │                                              │
│ 일반          │ ⚠ 오류 2                                     │
│ 구독     ●    │   [ico] Banksalad RSS     · 마지막 성공 3일 전 › │
│ AI           │ ▾ Tech blog                                   │
│ 저장 공간     │   [ico] 토스 기술 블로그    · 15분            › │
│              │   [ico] D2 Blog           · 1시간           › │
│              │ ▾ 미분류                                      │
│              │   [ico] The New Stack     · 15분            › │
└──────────────┴─────────────────────────────────────────────┘
                 행 클릭 → 오른쪽에서 상세 패널(또는 행 아래 펼침)
```

- **왼쪽 세로 내비게이션**으로 바꾸고 섹션을 `일반 · 구독 · AI · 저장 공간`으로 재편한다.
  - 헤더는 `‹ 돌아가기`와 섹션 제목만 남긴다. `PREFERENCES` 라벨, `Feed settings` 제목, 소개 문단은 제거한다.
  - 사이드바 ⚙ 버튼으로 열고, 기존처럼 `Esc` 또는 `‹ 돌아가기`로 닫는다. `?tab=` 쿼리는 `?section=`으로 이름만 바꿔 유지한다(사이드바·AI 패널에서 특정 섹션으로 바로 연결하기 위해).
- **일반**: 언어(§3.15), 테마(현 Appearance).
- **구독** (현 Feeds + Folders 통합):
  - 피드를 **폴더별로 묶은 얇은 행 목록**으로 보여준다: favicon · 제목 · 새로고침 주기 · 오류 표시.
    URL, 형식(RSS/Atom), 안 읽은 수, 다음 확인 시각 같은 메타 정보는 상세 화면으로 옮긴다.
  - 오류가 난 피드는 맨 위 `⚠ 오류 N` 그룹에 따로 모은다(해당 폴더에도 그대로 표시).
  - 상단에 **검색 입력**(제목·URL 필터)과 `+ 추가` 버튼(§3.11 다이얼로그를 그대로 사용)을 둔다.
  - **피드 상세는 오른쪽 패널로 연다 (결정됨)**: 행을 클릭하면 목록 오른쪽에 상세 패널이 열리고, 목록은 그대로 남는다.
    - 왜 오른쪽 패널인가: 여러 피드를 연달아 손볼 때 **다른 행을 한 번 클릭하면 바로 그 피드로 바뀐다.** 행 아래 펼침은
      열 때마다 목록이 아래로 밀려 위치를 잃고, 닫고 다시 여는 동작이 반복된다. 메인 화면의 "목록 | 리더"와 같은 구조라 익히기도 쉽다.
    - 아무 피드도 선택하지 않았을 때는 패널을 렌더링하지 않고 목록이 전체 폭을 쓴다(빈 "피드를 선택하세요" 화면을 두지 않음).
    - 선택한 행은 `--color-selection-bg`로 표시하고, `✕` 또는 같은 행을 다시 클릭하면 닫는다.
    - 창이 좁아 `세로 내비 + 목록 + 패널`이 들어가지 않으면(약 900px 미만) 패널이 목록 위에 겹쳐서 열린다.
    - 내용: 표시 이름(§3.16) · URL(복사 버튼) · 폴더 · 새로고침 주기 · `전체 보기에 포함` 스위치 · 마지막 오류 ·
      `지금 새로고침` · `구독 해제`(기존 `.confirm-row` 확인 유지). 변경은 즉시 저장한다.
    - 사이드바 오류 아이콘에서 넘어온 경우(`?section=subscriptions&feed=<id>`) 해당 피드를 선택한 상태로 연다.
  - 폴더 헤더 행에 hover 시 `이름 변경 · 삭제`, 목록 맨 아래에 `+ 새 폴더`를 둔다. `FolderSettings.svelte`의 인라인 이름 변경/삭제 확인 로직은 재사용한다.
  - 피드 행을 폴더 사이로 드래그해서 옮길 수 있게 사이드바의 드래그 로직을 재사용한다(select로 바꾸는 방법도 상세에 그대로 둔다).
- **AI** (신규):
  - 기본 provider(Codex / Claude) — §3.9의 `aequo:aiProvider`와 같은 값.
  - CLI 연결 상태: 각 CLI를 찾았는지, 로그인됐는지. `확인` 버튼으로 다시 검사한다.
    (현재 감지 커맨드가 없다면 `ai.rs`에 `check_ai_providers` 추가 — `--version` 실행 정도로 가볍게.)
  - AI 패널 푸터에 있던 안내: "로컬에 로그인된 CLI로 실행되며, Aequo에는 API 키를 저장하지 않습니다."
  - "Aequo에서 대화 기록을 지워도 CLI 자체 기록은 남는다"는 안내.
- **저장 공간**: `Save policy` 버튼을 없애고 select를 바꾸면 바로 저장한다(다른 설정과 저장 방식 통일).
  변경 후 짧은 "저장됨" 표시. `지금 정리하기`는 미리보기 문구(`N개 글 삭제 · 약 X MB 확보`)를 버튼 바로 옆에 두고,
  누르면 `.confirm-row` 확인을 거친다(되돌릴 수 없는 작업이므로).
- 모든 섹션에서 같은 행/라벨/설명 문구 스타일을 쓰는 `SettingsRow` 컴포넌트를 둔다(라벨 왼쪽, 컨트롤 오른쪽, 설명은 라벨 아래 회색 한 줄).

### 3.11 피드 추가 다이얼로그 (`AddFeedForm.svelte` 재사용)

데스크톱 RSS 앱(NetNewsWire, Reeder, Feedly, Inoreader)의 보편적 방식인 **`+` → 모달 다이얼로그**로 한다.
설정 화면으로 이동하면 읽던 맥락을 잃고, 좁은 사이드바 안의 인라인 입력은 긴 URL과 오류 메시지를 담기 어렵다.

```
┌ 피드 추가 ─────────────────────────────┐
│ URL  [https://toss.tech            ]  │  ← 열리면 자동 포커스
│ 폴더 [Tech blog ▾]                     │  ← 기본값: 현재 선택된 폴더, 없으면 미분류
│                                       │
│ (오류는 여기 .error-card)               │
│                         [취소] [추가]  │
└───────────────────────────────────────┘
```

- 여는 곳: 사이드바 `+`, 설정 > 구독의 `+ 추가`. 두 곳 모두 같은 컴포넌트(`AddFeedDialog.svelte`)를 쓴다.
- 내부 입력/제출/오류 처리는 `AddFeedForm.svelte`를 그대로 쓰고, 폴더 select만 추가한다(`add_feed` 성공 후 `updateFeedOrganization` 호출, 또는 `add_feed`에 `folder_id` 인자 추가).
- `<dialog>` 요소 + `showModal()` 사용: 포커스 가두기, `Esc` 닫기, 배경 클릭 닫기를 브라우저 기본 동작으로 얻는다.
- 추가에 성공하면 다이얼로그를 닫고, 사이드바에서 새 피드를 선택한 상태로 만든 뒤 "피드를 추가했습니다" 토스트를 띄운다.
- 클립보드 URL 자동 채우기는 하지 않는다(결정됨).

### 3.12 Favicon (백엔드 + 프론트)

**제약**: `tauri.conf.json`의 CSP가 `img-src 'self' asset: http://asset.localhost data:`라서 웹뷰가 외부 이미지 URL을 직접 불러올 수 없다.
이 제약은 프라이버시(읽는 동안 외부 서버로 요청이 나가지 않음) 측면에서도 유지할 가치가 있으므로,
**백엔드가 아이콘을 받아 DB에 저장하고 프론트에는 `data:` URI로 넘긴다.**

- **스키마** (`db/schema.rs`, 기존 멱등 패턴):
  ```sql
  CREATE TABLE IF NOT EXISTS feed_icons (
      feed_id    INTEGER PRIMARY KEY REFERENCES feeds(id) ON DELETE CASCADE,
      mime       TEXT NOT NULL,
      data       BLOB NOT NULL,
      source_url TEXT,
      fetched_at INTEGER NOT NULL
  );
  ```
  `feeds`에 컬럼을 추가하지 않고 별도 테이블로 둔다 — `listFeeds`가 자주 호출되므로 BLOB이 같이 실리지 않게 하기 위해서다.
- **아이콘 탐색 순서** (`fetch/favicon.rs` 신규):
  1. 피드 자체의 아이콘: JSON Feed `favicon`/`icon`, Atom `<icon>`/`<logo>`, RSS `<channel><image><url>` (`feed-rs`가 파싱한 값 사용)
  2. 사이트 홈(피드의 `link` 또는 피드 URL의 origin) HTML의 `<link rel="icon">` / `apple-touch-icon` — `discovery.rs`의 HTML 파싱을 재사용
  3. `<origin>/favicon.ico`
- **제한**: 응답 최대 64KB, `image/png|x-icon|vnd.microsoft.icon|svg+xml|jpeg|webp`만 허용. 기존 `fetch/client.rs`의 HTTP 클라이언트(타임아웃, UA)를 재사용한다.
  **SVG도 허용한다(결정됨).** 안전 조건:
  - SVG는 **반드시 `<img src="data:image/svg+xml;base64,…">`로만** 렌더링한다. `<img>`로 불러온 SVG는 스크립트 실행·외부 리소스 로드가
    브라우저 차원에서 막힌다. `{@html}`이나 인라인 `<svg>`로 넣는 코드 경로를 만들지 않는다(`FeedIcon.svelte`에 주석으로 명시).
  - 저장 전 백엔드에서 최소 검증: 내용이 `<svg`로 시작하는 XML인지 확인하고, 아니면 버린다. MIME은 응답 헤더가 아니라 내용으로 판단한다(sniffing).
  - CSP의 `img-src data:`는 이미 허용돼 있어 설정 변경은 필요 없다.
- **시점**: 피드를 추가할 때 백그라운드로 한 번 받는다. 이후에는 `fetched_at`이 30일 지났을 때 정기 수집 사이클에서 다시 받는다.
  기존 피드는 앱 시작 시 아이콘이 없는 피드만 순차로 받는다(동시 요청 수 제한).
  실패하면 빈 행을 저장하지 않고 `fetched_at`만 기록하는 대신, 7일 뒤에 다시 시도한다(실패 표시용 `mime = ''` 행 등).
- **커맨드**: `get_feed_icons() -> HashMap<i64, String>` (feed_id → `data:` URI). 프론트는 앱 시작 시 한 번 받아
  `$lib/feedIcons.svelte.ts` 스토어에 캐시하고, `feed-icon-updated` 이벤트가 오면 해당 항목만 갱신한다.
- **표시 위치**: 사이드바 피드 행(제목 왼쪽 14px), 글 목록 출처 줄(16px), 리더 헤더 출처, 설정 > 구독 행.
  공용 `FeedIcon.svelte`(아이콘 없으면 첫 글자 원으로 대체)를 만든다.
- **보관 정책 연동**: 구독 해제 시 `ON DELETE CASCADE`로 삭제. 저장 공간 미리보기 계산에는 포함하지 않는다(용량이 작음).
- **테스트**: 세 가지 탐색 경로 각각에 대한 fixture 테스트, 크기 초과/잘못된 MIME 거부 테스트.

### 3.13 타이포그래피 스케일 정리 (평가 이슈 2)

**현재**: `+layout.svelte`에 `--font-size-xs`(11px)~`--font-size-lg`(15px) 토큰이 있지만, 주석대로 "기존 컴포넌트는 em 기반 크기 유지"라서
실제로는 **서로 다른 `font-size` 값이 33가지** 쓰인다. 상위 사용 빈도: `0.82em`(12회) · `0.78em`(11) · `0.85em`(10) · `0.9em`(9) ·
`0.8em`(9) · `0.76em`(7) · `0.72em`(6) · `0.68em`(5) · `0.75em`(4) … 그리고 `0.62em`(AI rail 라벨)까지 있다.
눈으로 구분되지 않는 차이(0.76 / 0.78 / 0.8 / 0.82)가 화면을 미묘하게 어수선하게 만들고, 11px 미만 글자가 여러 곳에 생긴다.

**변경**:

- 크기를 **역할 기반 6단계**로 고정하고 px로 정의한다(em은 부모 크기에 따라 누적되어 예측하기 어렵다):

  | 토큰 | 크기 / 행간 | 용도 |
  |---|---|---|
  | `--text-caption` | 11px / 1.4 | 보조 메타(카운트, 시간, 힌트). **이보다 작은 글자는 쓰지 않는다** |
  | `--text-small` | 12px / 1.45 | 출처 줄, 설정 설명, 버튼 보조 텍스트 |
  | `--text-body` | 13px / 1.5 | 기본 UI 텍스트(사이드바, 목록 요약, 채팅) |
  | `--text-title` | 14px / 1.4 | 목록 글 제목, 섹션 제목 |
  | `--text-heading` | 17px / 1.3 | 설정 섹션 제목, 다이얼로그 제목 |
  | `--text-display` | 22px / 1.25 | 리더 글 제목 |

  리더 본문(`FeedContent` 비-compact)은 읽기용이라 별도 `--text-reading`(16px / 1.7)을 둔다.
- 굵기도 3단계로 묶는다: `--weight-regular` 400 · `--weight-medium` 550 · `--weight-bold` 650. 현재 섞여 있는 `620`, `650`, `600`, `700` 등을 매핑한다.
- 기존 `--font-size-*` 토큰은 새 토큰의 별칭으로 남겼다가, 사용처를 모두 옮긴 뒤 제거한다.
- **교체 방법**: 컴포넌트별로 `font-size: 0.xxem`을 가장 가까운 역할 토큰으로 바꾼다. 컴포넌트 단위로 커밋하고 스크린샷으로 전후를 비교한다.
- **회귀 방지**: `stylelint`의 `declaration-property-value-allowed-list`(또는 단순 grep 스크립트를 `pnpm check`에 추가)로
  `font-size`에 `var(--text-*)` 외의 값을 쓰면 실패하게 한다.
- 글꼴: 한국어 글이 많으므로 `font-family`에 `'Apple SD Gothic Neo'`를 명시적으로 넣고, 리더 본문에는 `word-break: keep-all`을 적용해
  한국어 어절 중간에서 줄바꿈되지 않게 한다.

### 3.14 RSS 리더 기본 기능 (평가 이슈 3)

현재 상태 확인 결과:
- `list_items`는 `unread_only` 인자를 지원하고 테스트도 있지만, `+page.svelte`는 항상 `false`로 호출한다 — **UI만 없다.**
- `mark_feed_read` 커맨드와 `markFeedRead()` API 래퍼가 있지만 **어떤 화면에서도 쓰지 않는다.** 폴더·전체 단위 일괄 읽음은 없다.
- `refresh_feed`(피드 1개)는 있지만 전체 새로고침 버튼은 메인 화면에 없다(설정 화면 피드별 `Refresh`만 있음).
- 글 검색이 없다. 읽음 → 안 읽음으로 되돌리기도 없다.

**변경**:

- **목록 상단 툴바** (`PostsFeed.svelte`의 `.feed-context` 줄을 확장):
  ```
  Tech blog  · 안 읽음 210           [전체 | 안 읽음]  ✓  ↻  🔍
  ```
  - `전체 | 안 읽음` 세그먼트 토글 → `listItems(..., unreadOnly)`. 선택은 localStorage `aequo:unreadOnly`에 저장한다(보기별로 따로 저장하지 않음).
    안 읽음 보기에서 글을 열어 읽음 처리돼도 **바로 목록에서 빼지 않는다** — 읽던 위치가 흔들리지 않도록 다음 새로고침/보기 전환 때 반영한다(NetNewsWire·Reeder 방식).
  - ✓ **모두 읽음 처리**: 현재 보기(피드 / 폴더 / 전체 / 오늘) 범위의 안 읽은 글을 읽음 처리한다.
    - 백엔드: `mark_feed_read`를 일반화한 `mark_items_read(scope)` 추가 — scope는 `{ feedId } | { folderId } | { all } | { publishedFrom, publishedTo }`,
      기준 시각 `before_published_at`(버튼을 누른 시점에 화면에 보이던 가장 최신 글)을 받아 그 사이에 새로 들어온 글은 건드리지 않는다.
      `hidden_from_all` 피드는 All 범위에서 제외(현재 `list_items`의 조건과 동일하게).
    - 확인 다이얼로그 대신 **실행 후 "N개를 읽음 처리했습니다 · 실행 취소" 토스트**를 띄운다(되돌리기 쉬운 작업은 확인보다 실행 취소가 보편적).
      실행 취소를 위해 백엔드가 영향받은 item id 목록을 반환하고, `mark_items_unread(ids)`로 되돌린다.
    - 사이드바 피드/폴더 컨텍스트 메뉴(§3.3)에도 같은 동작을 넣는다.
  - ↻ **새로고침**: 현재 보기 범위의 피드를 즉시 새로 받는다(`refresh_feed`를 범위 내 피드에 대해 호출하거나 `refresh_feeds(ids)` 추가).
    진행 중에는 아이콘이 회전하고, 끝나면 기존 `feed-updated` 이벤트 흐름으로 목록이 갱신된다.
  - 🔍 **검색**: 아이콘을 누르면 툴바가 검색 입력으로 바뀐다. 현재 보기 범위 안에서 검색한다.
    입력은 200ms 디바운스, `Esc`로 검색 종료 후 원래 목록 복귀. 결과는 기존 목록과 같은 최신순이고, 제목의 일치 부분을 `<mark>`로 강조한다.
    방식은 아래 "검색 설계"를 따른다.

**검색 설계 (결정됨: FTS5 trigram, 제목 + 요약 + RSS 본문)**

- **대상**: `items.title` + `items.summary` + `items.full_content`(피드가 RSS에 실어 보낸 본문). HTML은 태그를 제거한 plain text로 색인한다.
  - **추출된 전문(`article_cache.content_html`)은 색인하지 않는다.** 사용자가 열어 본 글에만 있고 보관 정책(§저장 공간)으로 지워지기도 해서,
    "어떤 글은 본문까지 검색되고 어떤 글은 안 되는" 일관성 없는 결과가 나온다. RSS 본문만으로도 전문을 싣는 피드는 대부분 커버된다.
- **왜 `LIKE`가 아니라 FTS5인가**: `LIKE '%…%'`는 글이 쌓일수록 매 검색마다 전체 본문을 훑는다. 본문까지 검색하려면 색인이 필요하다.
- **왜 기본 토크나이저가 아니라 `trigram`인가**: FTS5 기본 `unicode61`은 띄어쓰기로 단어를 나눈다. 한국어는 조사가 붙으므로
  "블로그에서"가 들어 있는 글을 "블로그"로 찾지 못한다. `trigram`(SQLite 3.34+)은 3글자 단위로 색인해 **부분 문자열 검색**이 되므로
  한국어·영어 모두 `LIKE '%…%'`와 같은 결과를 색인 속도로 얻는다.
  - 프로젝트는 `rusqlite` `bundled`(libsqlite3-sys 0.30 → SQLite 3.46)를 쓰므로 trigram을 쓸 수 있다. FTS5가 번들 빌드에서 켜져 있는지는
    UI13 시작 시 `CREATE VIRTUAL TABLE … USING fts5(…, tokenize='trigram')` 단위 테스트로 먼저 확인한다.
  - **trigram의 한계: 3글자 미만 검색어는 색인을 쓸 수 없다.** "보안", "AI" 같은 2글자 검색어가 흔하므로,
    검색어가 3글자 미만이면 **제목 + 요약만** `LIKE`로 검색하는 fallback을 둔다(본문까지 `LIKE`로 훑지 않아 느려지지 않음).
- **스키마** (`db/schema.rs`, 기존 멱등 패턴):
  ```sql
  CREATE VIRTUAL TABLE IF NOT EXISTS items_fts USING fts5(
      title, summary, body,
      content='', tokenize='trigram'
  );
  ```
  `rowid = items.id`. contentless(`content=''`)로 두어 본문을 두 번 저장하지 않는다.
  - 동기화는 SQL 트리거가 아니라 **Rust의 `upsert_items` / 아이템 삭제 경로에서 직접** 한다 — 색인 전에 HTML을 plain text로 바꿔야 하므로.
    보관 정책으로 아이템이 지워질 때(`commands/storage.rs`)도 함께 지운다.
  - 기존 데이터: 테이블이 새로 만들어진 첫 실행에 한 번 전체 재색인(백그라운드, 진행 중에는 `LIKE` fallback 사용).
- **쿼리**: 검색어를 `"…"` 구문으로 감싸 FTS 연산자(`AND`, `*`, `-` 등)가 해석되지 않게 한다(사용자 입력 그대로 일치).
  `list_items`에 `query: Option<String>`을 추가해 `id IN (SELECT rowid FROM items_fts WHERE items_fts MATCH ?)`로 기존 범위·커서 조건과 결합한다
  — 페이지네이션과 피드/폴더/안 읽음 필터가 그대로 동작한다.
- **용량**: trigram 색인은 원문의 2~3배 크기다. 보관 정책이 오래된 아이템을 지우면 색인도 같이 줄어든다.
  저장 공간 화면의 용량 미리보기에 색인 크기를 포함한다.
- **테스트**: 한국어 조사 결합어 부분 일치, 2글자 fallback, FTS 연산자 문자가 섞인 입력, 피드/폴더 범위 결합, 삭제 시 색인 제거.
- **안 읽음으로 표시**: 리더 헤더 `⋯` 메뉴와 글 목록 행의 우클릭 메뉴. 백엔드 `mark_unread(item_id)` 추가, 프론트는 `markPostRead`와 같은 낙관적 업데이트 + 롤백 패턴을 쓴다.
- **사이드바 안 읽은 수 동기화**: 일괄 읽음/안 읽음 처리 후 `refreshFeeds()`로 카운트를 맞춘다(낙관적으로 먼저 0으로 만들고, 실패 시 롤백).

### 3.15 UI 언어 · 날짜 형식 통일 (평가 이슈 4)

**현재**: 버튼·메뉴·빈 상태 문구는 모두 영어 하드코딩이고, 구독 글은 대부분 한국어다. 날짜는 `toLocaleString(undefined, …)`
5곳(`PostsFeed` 2, `PostReader`, `AiPanel`, `FeedSettings`)에서 웹뷰 기본 로케일을 따라 `11/15/26, 2:00 AM`처럼 미국식으로 나온다.
`src/app.html`은 `lang="en"` 고정이라 한국어 글에서도 영어 기준 줄바꿈·글꼴 선택이 적용된다.

**변경**:

- **경량 i18n 도입** (`src/lib/i18n/`): 외부 라이브러리 없이 `ko.ts` / `en.ts` 메시지 사전 + `t(key, params)` 함수 + 현재 로케일 rune 스토어.
  - 메시지 키는 화면 단위로 묶는다(`posts.empty.title`, `settings.storage.cleanup` …). 복수형은 `Intl.PluralRules`로 처리한다.
  - 기본 언어는 **시스템 언어**(`navigator.language`가 `ko`로 시작하면 한국어, 아니면 영어). 설정 > 일반에서 `시스템 / 한국어 / English`로 바꿀 수 있다.
  - 이 계획의 다른 절에서 새로 쓰는 문구(§3.9~§3.14)는 처음부터 `t()`로 작성한다. 기존 문구는 컴포넌트별로 옮긴다.
- **날짜·시간 유틸 통일** (`src/lib/format.ts`): `formatRelative()`(목록·채팅 기록), `formatDateTime()`(리더·설정), `formatDayHeading()`(날짜 그룹 제목).
  전부 현재 앱 언어를 `Intl.DateTimeFormat` / `Intl.RelativeTimeFormat`에 명시적으로 넘긴다. 5곳의 `toLocaleString(undefined…)`을 이 유틸로 교체한다.
  - 한국어 예: `2시간 전`, `11월 15일 (금) 오후 2:00`, 날짜 그룹 `11월 15일 금요일`.
- **`lang` 속성**: 앱 언어가 바뀌면 `document.documentElement.lang`을 함께 바꾼다. 리더 본문(`FeedContent`)에는 글 언어를 따로 지정한다 —
  피드의 `<language>` 값이 있으면 그것을, 없으면 앱 언어를 쓴다.
- **AI 답변 언어 (결정됨: 글의 언어를 따른다)**:
  - 빠른 질문 칩의 **라벨**은 앱 언어로 보여주지만, AI에게 보내는 프롬프트에는 "글이 쓰인 언어로 답하라"는 지시를 넣는다.
    한국어 블로그 글은 한국어로, The New Stack 글은 영어로 요약된다.
  - 글의 언어 판단: 피드의 `<language>`(RSS) / `xml:lang`(Atom) 값이 있으면 그것을 프롬프트에 명시한다(`Respond in ko.`).
    값이 없는 피드가 많으므로, 없을 때는 모델에게 "본문의 언어로 답하라"고만 지시한다 — 별도 언어 감지 라이브러리는 넣지 않는다.
    이를 위해 `feeds.language` 컬럼을 추가하고 파서에서 저장한다(§3.15 `lang` 속성 지정에도 같은 값을 쓴다).
  - 사용자가 **직접 입력한 질문**은 일반 채팅 관례대로 질문한 언어로 답하게 한다(영어 글에 한국어로 물으면 한국어로 답).
    즉 "글의 언어"는 사용자가 언어를 드러내지 않은 빠른 질문·선택 영역 질문의 기본값이다.
- **테스트**: 컴포넌트 테스트가 영어 문구로 요소를 찾고 있으므로, 테스트 환경 로케일을 `en`으로 고정해 기존 테스트를 깨지 않게 하고,
  `ko` 사전에 `en`의 모든 키가 있는지 검사하는 테스트를 추가한다.

### 3.16 피드가 많을 때의 탐색 (평가 이슈 5, §3.3·§3.10 보완)

설정 화면 재구성(§3.10)과 사이드바 정리(§3.3)에 더해, 메인 화면 사이드바에서 피드가 20~30개 이상일 때를 위한 보완:

- **잘린 이름 툴팁**: 사이드바 피드/폴더 행에 `title` 속성으로 전체 이름을 넣는다. `⋮`가 hover로 숨으면서(§3.3) 이름 폭도 넓어진다.
- **이름 정리**: §3.1의 `shortFeedTitle()`을 사이드바에도 적용한다. 사용자가 피드 이름을 직접 바꿀 수 있게 설정 > 구독 상세에
  `표시 이름` 필드를 추가한다(백엔드 `feeds.custom_title` 컬럼 + `rename_feed` 커맨드. 수집 시 원래 `title`은 계속 갱신되고 표시는 `custom_title`을 우선).
- **폴더 접힘 상태 저장**: 현재 `collapsedFolders`는 메모리의 `SvelteSet`이라 앱을 다시 켜면 모두 펼쳐진다.
  localStorage `aequo:collapsedFolders`(폴더 id 배열)에 저장하고, 삭제된 폴더 id는 읽을 때 걸러낸다.
- **안 읽은 글이 없는 피드 (결정됨: 별도 옵션 없이 "안 읽음" 토글 하나로 처리)**:
  - 기본(`전체` 보기)에서는 숨기지 않고 **흐리게**(`--color-text-secondary`) 표시한다. 피드 목록이 갑자기 줄거나 늘지 않아 위치 기억이 쉽다.
  - 목록 툴바의 `전체 | 안 읽음` 토글(§3.14)이 `안 읽음`이면 **사이드바도 같이** 안 읽은 글이 없는 피드와 폴더를 숨긴다
    (Reeder·Feedbin·NetNewsWire의 "안 읽은 항목만" 방식). 설정 항목을 따로 두지 않고 토글 하나로 "읽을 것만 보기"가 완성된다.
  - 예외: **현재 선택된 피드/폴더는 0개가 되어도 숨기지 않는다** — 마지막 글을 읽는 순간 선택 항목이 사이드바에서 사라지는 혼란을 막는다.
    다른 보기로 옮겨 가면 그때 숨긴다.
  - 고정 항목(All · Today · Starred)은 항상 보인다. 모든 피드가 숨겨지면 사이드바에 "모두 읽었습니다" 한 줄을 보여준다.
- **오류 피드 표시**: 이미 있는 `.feed-health` 아이콘을 유지하고, 클릭하면 설정 > 구독의 해당 피드 상세로 바로 이동한다(`?section=subscriptions&feed=<id>`).

## 4. 접근성 / 회귀 주의점

- hover 전용으로 숨기는 모든 컨트롤은 `:focus-visible`/`:focus-within`에서도 보여야 한다(키보드 사용자).
- 안 읽음을 굵기로만 구분하면 색약·저시력 사용자에게 약할 수 있다 → 명도 차이(text vs. text-secondary)를 함께 쓴다.
- `prefers-reduced-motion` 처리(`+layout.svelte`)는 그대로 유지.
- `grid-template-columns` transition은 트랙 모양이 같아야 보간된다(`+page.svelte` 주석) — AI rail 제거 시
  닫힘 상태의 AI 트랙을 `0px`로 두어 7트랙 구조는 유지한다.
- 기존 컴포넌트 테스트(`PostsFeed.test.ts`, `FeedList.test.ts`)가 `.unread-dot`, `Manage feeds` 텍스트 등에 의존하는지 확인하고 갱신.

## 6. 결정됨

- 기능은 빼지 않고 노출 방식만 바꾼다.
- AI 패널은 오버레이가 아니라 grid 트랙으로 유지한다(본문을 가리지 않음).
- 요약 꼬리 문구는 파서에서 제거한다.
- 토큰 값은 유지하고 사용처만 정리한다.
- **AI 패널은 글이 열려 있을 때만 표시한다.** 연 상태는 기억해서 다음 글을 열 때 다시 열린다(리더 앱의 보편적 방식, §2).
- **목록 요약은 최대 2줄.**
- **Favicon을 이번 범위에 넣는다.** 백엔드가 받아 DB에 저장하고 `data:` URI로 전달한다(CSP 유지, §3.12).
- **`+` 버튼은 피드 추가 모달 다이얼로그를 연다**(데스크톱 RSS 앱의 보편적 방식, §3.11).
- 설정 화면 재구성(§3.10)과 AI 채팅 패널 정리(§3.9)를 이 계획 범위에 포함한다.
- **UI 언어는 한국어·영어 둘 다 지원**하고 기본값은 시스템 언어(§3.15).
- **AI 답변 언어는 글(RSS 피드)의 언어를 따른다.** 단, 사용자가 직접 입력한 질문은 질문한 언어로 답한다(§3.15).
- **안 읽은 글이 없는 피드는 별도 옵션 없이 `안 읽음` 토글에 연동해 숨긴다.** `전체` 보기에서는 흐리게만 표시한다(§3.16).
- **검색은 SQLite FTS5 `trigram`으로 제목 + 요약 + RSS 본문을 색인한다.** 추출된 전문은 제외하고, 3글자 미만 검색어는 제목·요약 `LIKE`로 처리한다(§3.14).

- **키보드 단축키는 만들지 않는다**(§3.8).
- **대화 중 provider를 바꾸면 확인 없이 새 대화를 시작하고, 이전 대화로 돌아가는 링크를 남긴다**(§3.9).
- **피드 추가 창에서 클립보드 URL 자동 채우기는 하지 않는다**(§3.11).
- **SVG favicon을 허용한다.** `<img>` + `data:` URI로만 렌더링한다(§3.12).
- **설정의 피드 상세는 목록 오른쪽 패널로 연다**(§3.10).
- **AI 스트리밍 응답을 포함해 이 계획 전체를 v1.0.0에 넣는다**(§3.9, UI10).
